# Analogies

An analogy is a conceptual mapping between an Indian mythological object, story, tale, or incident
and a modern scientific or technological concept. An analogy is **not** a theory and **not** a
mechanism — it is a starting spark that may or may not turn into something testable.

Copy [`templates/ANALOGY.md`](../templates/ANALOGY.md) to create a new analogy file, name it `A###_short-name.md` (e.g.
\(A001_samudra_manthan.md\)), and add a row to the index table below.

## Rules

### Icon key

Use icons as semantic signposts: 📖 source story, 🗺️ mapping, 💡 purpose, ✅ suggested value,
⚠️ limits, 🧪 testable component, 🪞 metaphor, 🔬 known science, and 📚 provenance.

Use one short evidence label below each visual as a reader-facing sticker:
🔴 boundary/closed, 🟠 active investigation, 🟣 open question, 🟢 mathematics or pretest result,
⚪ analogy-only, and 🔵 historical record. The label must clarify evidence status, not decorate it.

- Preserve the mythological source as given (which text, which version, which incident) without
  altering it to fit the science better.
- Clearly separate what the analogy **suggests** from what it **proves**. It proves nothing by
  itself.
- Mark the testable component (if any) versus the purely metaphorical component.
- One analogy can be used by multiple lines of thought; do not duplicate the file, link to it.
- When a visual adds explanatory value, embed a small local schematic from `../assets/analogies/`.
  Give it meaningful alt text and a short caption stating which properties are being mapped.
- Visuals must clarify the analogy, not imply historical authenticity or scientific proof. Label
  conceptual reconstructions as schematics and keep them modest in size.
